## 1. מטרה ותחום

כל משחק שמסתיים בניצחון או בהפסד נשמר **פעם אחת** ב-`localStorage` (עד 10 רשומות, מהחדש לישן). מסך **"אודות"** מציג את הרשומות ככרטיסים, חיווי ריק כשאין, וכפתור **"מחק היסטוריה"** שפותח חלונית אישור עם **"ביטול"** / **"מחק"**. כשל אחסון מוצג בעברית ואינו חוסם משחק.

**מחוץ לתחום:**

## 3. History Repository – `historyRepository.ts`

לפי מודל הנתונים ב-ARCHITECTURE 2.5:

```ts
type GameResult = {
  id: string            // e.g. `${Date.now()}-${gameId}`
  finishedAt: string    // ISO 8601 (new Date().toISOString())
  completedRounds: number // 0–10
  outcome: 'win' | 'loss'
}
type HistoryData = { schemaVersion: 1; results: GameResult[] }

const STORAGE_KEY = 'simon.history.v1'
const MAX_RESULTS = 10

type LoadResult = { ok: true; results: GameResult[] } | { ok: false; results: [] }
type WriteResult = { ok: true; results: GameResult[] } | { ok: false }

loadHistory(): LoadResult
addResult(current: GameResult[], result: GameResult): WriteResult  // newest first, keep first 10
clearHistory(): WriteResult                                        // removeItem(STORAGE_KEY)
```

- כל גישה ל-`localStorage` עטופה ב-`try/catch` (גישה ל-`window.localStorage` עצמה עלולה לזרוק במצבי פרטיות/חסימה).
- **קריאה:** מפתח חסר → `ok: true`, רשימה ריקה. JSON פגום או מבנה לא תקין (`schemaVersion !== 1`, `results` שאינו מערך) → `ok: false`. רשומה בודדת לא תקינה (שדה חסר, `completedRounds` מחוץ ל-0–10, `outcome` לא מוכר, תאריך לא חוקי) מסוננת החוצה; הרשימה נחתכת ל-10.
- **הוספה:** `[result, ...current].slice(0, 10)` → `setItem`. בכשל – `ok: false`, והרשימה בזיכרון **אינה** מתעדכנת כאילו נשמרה.
- **מחיקה:** `removeItem`. בכשל – `ok: false`; הרשימה נשארת כפי שהייתה (אין לטשטש כישלון כהצלחה).
- ה-Repository לא נוגע במצב המשחק; נשמרים רק ארבעת השדות של `GameResult`.

## 4. שמירה בסיום משחק – `useHistory.ts` + `App.tsx`

- `useHistory()` טוען פעם אחת בעלייה (`useState` עם פונקציית אתחול) ומחזיר:
  `{ results, loadFailed, saveFailed, deleteFailed, saveResult(gameId, outcome, completedRounds), clear() }`.
- **מניעת שמירה כפולה:** `useRef` שמחזיק את ה-`gameId` האחרון שנשמר. `saveResult` יוצא מיד אם ה-`gameId` כבר נשמר. כך גם הרצה כפולה של Effects ב-StrictMode, גם רינדור חוזר וגם חזרה מ"אודות" כשהמשחק עדיין במצב `won`/`lost` – לא יוצרים רשומה נוספת.
- `App.tsx`: `useEffect` התלוי ב-`state.status` וב-`state.gameId`; כשהסטטוס `won`/`lost` → `saveResult(state.gameId, ...)` (`won` → `'win'`, `lost` → `'loss'`). ה-Reducer נשאר נקי מ-`localStorage` (כלל עבודה 4).
- מצבי `paused`, ניווט ו-Refresh אינם `won`/`lost`, ולכן אינם נשמרים. Refresh מאפס את המשחק ל-`idle` בלי רשומה.
- כשל שמירה: `saveFailed = true` (המשחק ממשיך כרגיל; "שחק שוב" עובד). שמירה מוצלחת מאוחרת יותר מאפסת את הדגל.

## 5. ממשק – מסך "אודות"

מבנה לפי Wireframe "אודות" ו-DESIGN 1.2:
1. כותרת **"אודות"** וכרטיס **"על המשחק"** – ללא שינוי.
2. כותרת **"10 המשחקים האחרונים"** – קיימת.
3. **הודעת שגיאה** (אם יש), בטקסט בעברית, `role="alert"`:
   - טעינה נכשלה: **"לא ניתן לטעון את היסטוריית המשחקים במכשיר זה."**
   - שמירה נכשלה: **"לא ניתן היה לשמור את תוצאת המשחק האחרון."**
   - מחיקה נכשלה: **"מחיקת ההיסטוריה נכשלה. נסה שוב."**
4. **רשימת כרטיסים** (`<ol>`, מהחדש לישן). כל כרטיס (לפי ה-Wireframe):
   - בצד אחד **"שלבים שהושלמו: X"** ו-**"תוצאה: ניצחון"** / **"תוצאה: הפסד"** – התוצאה בטקסט, עם הדגשת צבע מאופקת (ירוק/אדום) כתוספת בלבד.
   - בצד השני תאריך ושעה בגופן Caption, מעוצבים מ-`finishedAt` לפי Locale עברי וזמן מקומי: `DD.MM.YYYY HH:mm` (באמצעות `Intl.DateTimeFormat('he-IL', …)`), עם `unicode-bidi: isolate` כדי שהמספרים לא יתהפכו ב-RTL.
   - הטקסט מוצג כטקסט React רגיל (ללא `dangerouslySetInnerHTML`).
5. **חיווי ריק** "עדיין אין משחקים שמורים" – כשאין רשומות (הקיים).
6. כפתור **"מחק היסטוריה"** מתחת לרשימה – בסגנון Secondary/Destructive מאופק (קו מתאר אדום, לא הכפתור הכחול הראשי). **מוצג רק כשיש רשומות**: כשאין מה למחוק, הכפתור אינו מופיע (החיווי הריק מספיק).
- רשימה ארוכה גוללת בתוך העמוד; פס הניווט נשאר במקומו (המבנה הקיים של `app-content`).

## 6. Dialog אישור מחיקה – `ConfirmDialog.tsx`

לפי DESIGN 1.3 ו-Wireframe "אודות – אישור מחיקה":
- שכבת Scrim כהה מעל מסך אודות (`position: fixed`, מעל התוכן ומתחת/מעל הניווט – מכסה את כל המסך), כרטיס מרוכז **בהיר** (כמו ב-Mockup), פינות מעוגלות.
- כותרת **"למחוק את ההיסטוריה?"** (נוסח ה-DESIGN), הסבר קצר: **"כל תוצאות המשחקים השמורות יימחקו."**
- שני כפתורים בשורה, בסדר RTL כמו ב-Wireframe: **"ביטול"** (משני, אפור) ו-**"מחק"** (אדום).
- נגישות: `role="alertdialog"`, `aria-modal`, `aria-labelledby`/`aria-describedby`; פוקוס ראשוני על **"ביטול"** (הבחירה הבטוחה); מקש Escape = ביטול.
- **"ביטול"** → סוגר בלי שום שינוי ובלי קריאה ל-`localStorage`.
- **"מחק"** → `clear()`: הצלחה → רשימה ריקה + חיווי ריק; כשל → הרשימה נשארת + הודעת כשל מחיקה. בשני המקרים החלונית נסגרת.
- זו שכבה בתוך מסך אודות, לא מסך שלישי. מעבר ל-"בית" בזמן שהחלונית פתוחה אינו אפשרי (ה-Scrim מכסה גם את פס הניווט).

## 7. בדיקות אוטומטיות

**`historyRepository.test.ts`** (עם `localStorage` של jsdom, ו-`vi.spyOn(Storage.prototype, …)` לסימולציית כשל):
- טעינה ממפתח ריק → רשימה ריקה, `ok: true`.
- הוספה שומרת בראש הרשימה; 11 הוספות → 10 רשומות, הישנה ביותר הוסרה, סדר מהחדש לישן.
- JSON פגום / `schemaVersion` שגוי → `ok: false` בלי קריסה; רשומות לא תקינות מסוננות.
- `setItem` זורק → `ok: false`; `removeItem` זורק → `ok: false`; גישה ל-`localStorage` שזורקת → טעינה `ok: false`.
- מחיקה מסירה את המפתח.

**`History.test.tsx`** (רינדור `App` בתוך `StrictMode`, Timers מדומים ואודיו מדומה כמו בבדיקות M2/M3):
- הפסד בשלב 1 → מעבר ל-"אודות" מציג כרטיס אחד: "שלבים שהושלמו: 0", "תוצאה: הפסד".
- ניצחון (10 שלבים) → כרטיס "שלבים שהושלמו: 10", "תוצאה: ניצחון".
- **בדיוק רשומה אחת** למשחק גם תחת StrictMode, וגם אחרי מעבר הלוך-חזור בין המסכים כשהמשחק עדיין מציג את חלונית הסיום.
- השהיה, מעבר מסכים באמצע משחק ו-Unmount/Remount (מדמה Refresh) → אין רשומה.
- רשומות שנשמרו לפני רינדור מחדש של האפליקציה (מדמה Refresh) מוצגות שוב.
- 11 משחקים (מוזרקים ל-`localStorage` + משחק אחד) → 10 כרטיסים, החדש ראשון.
- "מחק היסטוריה" → "ביטול": הרשימה ו-`localStorage` ללא שינוי. → "מחק": חיווי ריק, המפתח הוסר.
- כשל `setItem` → המשחק מסתיים ו-"שחק שוב" עובד; ב-"אודות" מוצגת הודעת כשל שמירה. כשל `removeItem` → הרשימה נשארת והודעת כשל מחיקה מוצגת. כשל קריאה → הודעת טעינה, ו-"התחל" עדיין עובד.
- אין כפתור "מחק היסטוריה" כשהרשימה ריקה.

## 9. ADR שיתווסף ל-ARCHITECTURE.md

**ADR-6: שמירת תוצאה פעם אחת לפי `gameId`**
- **הקשר:** ב-StrictMode Effects רצים פעמיים, ומצב `won`/`lost` נשאר פעיל בזמן מעבר בין מסכים; Effect שמגיב לסיום משחק עלול לשמור יותר מפעם אחת.
- **החלטה:** השמירה מתבצעת ב-Hook `useHistory` (לא ב-Reducer), ו-`useRef` זוכר את ה-`gameId` האחרון שנשמר; קריאה חוזרת עם אותו `gameId` מתעלמת. ה-Repository מחזיר תוצאת הצלחה/כשל במקום לזרוק, והממשק מציג הודעה בעברית.
- **השלכות:** בדיוק רשומה אחת לכל משחק שהסתיים; כשל אחסון לא משפיע על המשחק; ה-Reducer נשאר טהור.
