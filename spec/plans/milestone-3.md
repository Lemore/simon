## 1. מטרה ותחום

משחק פעיל (`presenting` / `awaitingInput`) מושהה כשעוברים ל-**"אודות"**, כשהאפליקציה מוסתרת (מעבר לאפליקציה אחרת / נעילת טלפון) או ב-`pagehide`. ההשהיה עוצרת מיד הארה וצליל, שומרת את הרצף והשלב בזיכרון ומאפסת קלט חלקי. חזרה למסך הבית מציגה מצב מושהה עם **"המשך משחק"**; רק לחיצה עליו מציגה מחדש את הרצף **המלא** של אותו שלב.

**בתחום:** מצב `paused`; פעולות `PAUSE` / `RESUME`; Guard נגד Callbacks מיושנים; האזנה ל-`visibilitychange` ו-`pagehide`; השהיה לפני ניווט לאודות; UI של מצב מושהה; הפעלת אודיו מחדש מתוך הלחיצה על "המשך משחק"; בדיקות.

**מחוץ לתחום:**
- היסטוריה ו-`localStorage` – Milestone 4 (ב-M3 אין כתיבה לאחסון; משחק מושהה בוודאי לא נרשם).
- PWA / Offline – Milestone 5.
- שמירת משחק מושהה מעבר ל-Refresh – **לא** נדרש (ה-PRD קובע שרענון מאפס).

## 3. Game Engine – Reducer

```ts
type GameStatus = 'idle' | 'presenting' | 'awaitingInput' | 'paused' | 'won' | 'lost'

type GameState = {
  ...                    // as in M2
  presentationId: number // increments every time a presentation starts (START, next round, RESUME)
}

type GameAction =
  | { type: 'START'; firstColor: SimonColor }
  | { type: 'PRESENTATION_DONE'; presentationId: number }  // was: gameId
  | { type: 'PRESS'; color: SimonColor; nextColor: SimonColor }
  | { type: 'PAUSE' }
  | { type: 'RESUME' }
```

כללים:
- **`PAUSE`**: רק מ-`presenting` או `awaitingInput` → `paused`, `inputIndex = 0`. `sequence`, `round`, `completedRounds`, `gameId` ללא שינוי. מכל מצב אחר (כולל `paused` עצמו) – ללא שינוי (השהיה כפולה בטוחה).
- **`RESUME`**: רק מ-`paused` → `presenting`, `inputIndex = 0`, `presentationId + 1`; הרצף והשלב ללא שינוי (אין צבע חדש). מכל מצב אחר – ללא שינוי (מגן מפני Resume כפול).
- **`PRESENTATION_DONE`**: מתקבל רק אם `status === 'presenting'` **וגם** `presentationId` תואם להצגה הנוכחית. כך סיום של הצגה שבוטלה (לפני השהיה) לא יכול להעביר את התור לשחקן בהצגה החדשה.
- `START` ו-`PRESS`: ללא שינוי, מלבד ש-`START` חסום גם מ-`paused` (במצב מושהה הפעולה היחידה היא "המשך משחק"), ושניהם מעלים את `presentationId` כשמתחילה הצגה.
- `PRESS` ב-`paused` מתעלם (כבר נכון, כי מותר רק ב-`awaitingInput`).
- `paused` אינו `lost`: אין שינוי ב-`completedRounds` ואין מעבר למצב סיום.

## 4. Hook – `useGame.ts`

- **Effect ההצגה**: תלוי ב-`state.status` ו-`state.presentationId` (במקום `gameId`). כשהסטטוס יוצא מ-`presenting` (ל-`paused`), ה-Cleanup מבטל את ה-`AbortController` → Timers מתבטלים, `stopAll()`, `onLight(null)` (המנגנון הקיים ב-`playback.ts`).
- **`pause()`**: `dispatch({ type: 'PAUSE' })`, ובנוסף ניקוי מיידי של מה שלא שייך ל-Playback: `clearTimeout` לטיימר הארת הלחיצה, `setLitColor(null)`, `stopAll()` (עוצר צליל לחיצה שעדיין מתנגן). בטוח לקרוא לה בכל מצב – ה-Reducer מתעלם כשאין משחק פעיל.
- **`resume()`**: אסינכרונית, בדומה ל-`start()`:
  1. אם כבר יש Resume בתהליך (`useRef` דגל) – לצאת (מונע לחיצה כפולה מהירה בזמן ש-`unlockAudio()` ממתין).
  2. `await unlockAudio()` מתוך ה-Gesture (בטלפון ה-`AudioContext` עלול להיות מושעה אחרי חזרה מרקע).
  3. כשל → `audioError = true`, המשחק נשאר `paused` עם הכפתור, כדי לנסות שוב. הצלחה → `audioError = false`, `dispatch({ type: 'RESUME' })`.
  4. אם בזמן ההמתנה האפליקציה הוסתרה שוב – ה-Reducer כבר במצב `paused` ו-`RESUME` לא יקרה לפני הסתרה; ואם `RESUME` נשלח והאפליקציה הוסתרה אחריו – אירוע ההסתרה ישהה שוב כרגיל.
- **אירועי מערכת**: `useEffect` אחד שמוסיף מאזינים ל-`document` `visibilitychange` (כש-`document.visibilityState === 'hidden'`) ול-`window` `pagehide`, ושניהם קוראים ל-`pause()`. חזרה ל-`visible` **לא** עושה דבר (אין Resume אוטומטי). המאזינים מוסרים ב-Unmount.
- `pressPad` נשאר מוגבל ל-`awaitingInput`.
- מחזיר: `{ state, litColor, audioError, start, resume, pause, pressPad }`.

## 5. App Shell – ניווט

- `App.tsx`: פונקציית מעבר מסך שקוראת ל-`pause()` **לפני** `setScreen('about')`. מעבר ל-"בית" לא קורא לשום פעולת משחק (אין Resume אוטומטי).
- ה-Hook נשאר ב-`App`, כך שהמצב המושהה נשמר בזמן שמסך הבית אינו מוצג.
- Refresh: ללא שינוי – המצב בזיכרון בלבד ומתאפס ל-`idle`.

## 6. ממשק – מסך הבית (מצב מושהה)

לפי DESIGN.md ו-Wireframe "בית – משחק מושהה":
- חיווי שלב: **"שלב X מתוך 10"** – אותו שלב כמו לפני ההשהיה.
- טקסט סטטוס: **"המשחק מושהה"**.
- לוח: כל הרבעים מעומעמים (`dimmed` כשאין צבע דלוק) וחסומים ללחיצה (`inputEnabled = false`).
- כפתור ראשי: **"המשך משחק"** (`PrimaryButton` הקיים), רק במצב `paused`. לא מופיע ב-`idle`, `presenting`, `awaitingInput`, `won`, `lost`.
- כשל אודיו בחידוש: אותה הודעה קיימת בעברית ("לא ניתן להפעיל את הצלילים. נסה ללחוץ שוב."), והכפתור נשאר.
- לאחר לחיצה: מעבר ל-"המשחק מציג את הרצף" – הרצף המלא מוצג שוב מההתחלה (כולל ה-Lead-in הקבוע), ואז "התור שלך" עם קלט מהתחלה.

## 7. מקרי קצה שמטופלים

| מצב | התנהגות |
|---|---|
| השהיה באמצע הצגת הרצף | ההארה והצליל נעצרים מיד; Timers שנותרו מבוטלים; סיום ההצגה הישנה לא מגיע (ואם יגיע – נדחה לפי `presentationId`) |
| השהיה באמצע שחזור (חלק מהרצף כבר הוקש) | `inputIndex` מתאפס; לאחר חידוש יש לשחזר מההתחלה |
| השהיה מיד אחרי לחיצה (הארת לחיצה / צליל פעילים) | הארה מתנקה וצליל נעצר מיד |
| השהיה בזמן המעבר לשלב הבא (הלחיצה האחרונה הייתה נכונה, ההצגה החדשה עוד לא התחילה) | המצב הוא כבר `presenting` של השלב החדש → מושהה בשלב החדש; חידוש מציג את הרצף החדש המלא |
| הסתרה כשאין משחק פעיל (`idle` / `won` / `lost`) | אין שינוי; אין כפתור "המשך משחק" |
| `visibilitychange` ו-`pagehide` ברצף / ניווט לאודות ואז הסתרה | השהיה כפולה מתעלמת; מצב יציב |
| לחיצה כפולה מהירה על "המשך משחק" | הצגה אחת בלבד (דגל בתהליך + Reducer מתעלם מ-`RESUME` שלא מ-`paused`) |
| לחיצות על הלוח במצב מושהה | הכפתורים חסומים, וה-Reducer מתעלם בכל מקרה |
| חזרה מהרקע | נשאר `paused` עד לחיצה; אין Resume אוטומטי |

## 8. ADR

**ADR-4: השהיה – מזהה הצגה ונקודות השהיה**
- **הקשר:** אחרי השהיה וחידוש מתחילה הצגה חדשה של אותו משחק, ולכן `gameId` לבדו אינו מבדיל בין הצגה שבוטלה להצגה החדשה.
- **החלטה:** מונה `presentationId` ב-State שעולה בכל תחילת הצגה; `PRESENTATION_DONE` מתקבל רק אם המזהה תואם. ההשהיה מופעלת מ-3 נקודות: ניווט לאודות (ב-`App` לפני החלפת מסך), `visibilitychange` ל-`hidden`, ו-`pagehide`. חידוש מפעיל מחדש את האודיו מתוך הלחיצה.
- **השלכות:** Callbacks מיושנים נדחים גם אם ביטול ה-Timers נכשל; השהיה כפולה וחידוש כפול בטוחים.

## 9. בדיקות אוטומטיות

**`gameReducer.test.ts`:**
- `PAUSE` מ-`presenting` ומ-`awaitingInput` (עם `inputIndex > 0`) → `paused`, `inputIndex = 0`, רצף/שלב/`completedRounds` ללא שינוי.
- `PAUSE` מ-`idle`/`won`/`lost`/`paused` – ללא שינוי.
- `RESUME` מ-`paused` → `presenting`, אותו רצף (אותו אורך, אותם צבעים), אותו שלב, `presentationId` גדל.
- `RESUME` מכל מצב אחר – ללא שינוי (Resume כפול).
- `PRESENTATION_DONE` עם `presentationId` ישן – נדחה; עם הנוכחי – מתקבל.
- `PRESS` ו-`START` ב-`paused` – ללא שינוי; `paused` לעולם לא הופך ל-`lost`.

**בדיקות אינטגרציה (Fake Timers, Mock לאודיו כמו ב-M2):**
- ניווט ל-"אודות" באמצע הצגת רצף → `stopAll` נקרא, אין צבע דלוק, וקידום זמן לא מפעיל צלילים נוספים ולא מעביר לתור השחקן.
- ניווט ל-"אודות" באמצע שחזור (אחרי לחיצה נכונה אחת בשלב 2+) → חזרה ל-"בית" מציגה "המשחק מושהה", אותו שלב, וכפתור "המשך משחק".
- חזרה ל-"בית" וקידום זמן ארוך → לא מתנגן שום צליל ואין הצגה (אין Resume אוטומטי).
- לחיצה על "המשך משחק" → מוצג הרצף המלא (מספר הצלילים = אורך הרצף, באותו סדר), אחר כך "התור שלך"; שחזור מההתחלה מקדם לשלב הבא כרגיל.
- `visibilitychange` ל-`hidden` ו-`pagehide` → אותה השהיה; חזרה ל-`visible` לא מחדשת.
- לחיצה כפולה על "המשך משחק" → הרצף מוצג פעם אחת בלבד.
- כשל `unlockAudio` ב-"המשך משחק" → הודעת שגיאה, נשאר מושהה עם הכפתור.
- "המשך משחק" לא מופיע לפני התחלה ובמסך סיום (ניצחון/הפסד).
- Unmount/Remount של `App` (מדמה Refresh) → מצב התחלה.
- כל בדיקות M1/M2 ממשיכות לעבור; `npm run typecheck` ו-`npm run build` עוברים.

## 10. בדיקה ידנית (בבנייה, בדפדפן עם אמולציית מובייל)

1. התחלת משחק → מעבר ל-"אודות" באמצע הצגת הרצף → ההארה והצליל נעצרים מיד.
2. חזרה ל-"בית" → "המשחק מושהה", לוח מעומעם, אותו שלב, כפתור "המשך משחק"; המתנה של כמה שניות – לא קורה כלום.
3. "המשך משחק" → כל הרצף מוצג מחדש, אחר כך תור השחקן.
4. באמצע שחזור (אחרי חלק מהצבעים) → מעבר לאודות וחזרה → "המשך משחק" → הרצף המלא שוב, ושחזור מההתחלה עובד.
5. החלפת לשונית בדפדפן (מדמה רקע) וחזרה → מושהה, בלי Resume אוטומטי.
6. Refresh במצב מושהה → מסך התחלה עם "התחל".
7. בדיקה במכשיר אמיתי (נעילת טלפון / מעבר אפליקציה) – אם אפשר במסגרת הבנייה; אחרת יסומן במפורש כבדיקה שלא בוצעה ותושלם בבדיקה שלך / ב-Milestone 5.

## 11. מיפוי ל-Definition of Done

| תנאי | איך מאומת |
|---|---|
| מעבר ל-"אודות" בזמן הצגה ובזמן שחזור משהה ועוצר מיד הארה וצליל | בדיקות אינטגרציה (ניווט בהצגה ובשחזור) + בדיקה ידנית 1, 4 |
| חזרה ל-"בית" לא מפעילה רצף; "המשך משחק" רק במשחק מושהה | בדיקות "אין Resume אוטומטי" ו"הכפתור לא מופיע ב-idle/סיום" + בדיקה ידנית 2 |
| "המשך משחק" מציג את כל הרצף, גם אם חלק הוקש; שלב ללא שינוי ואין צבע חדש | בדיקות Reducer (`RESUME`) ובדיקת אינטגרציה של ספירת הצלילים + בדיקה ידנית 3–4 |
| הסתרה וחזרה לפי אותו כלל, ללא שינוי מ-Callback שבוטל | בדיקות `visibilitychange`/`pagehide` ו-`presentationId` ישן + בדיקה ידנית 5, 7 |
| משחק מושהה אינו הפסד; Refresh מאפס | בדיקות Reducer (לא `lost`) ו-Remount + בדיקה ידנית 6 |
